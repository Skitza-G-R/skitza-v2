# SK-255 UX grill checkpoint

**Date:** 20 August 2026; latest UX override 21 August 2026
**Status:** Approved for implementation by Gili on 20 August 2026.
**Authority:** Gili's latest explicit decision in SK-255 wins, then PRD v5.4. The older audited plan and the already-built UI are context, not authority for this redesign.

## Why this checkpoint exists

The first implemented UI was technically responsive but visually wrong. It treated a bulk setup tool like a marketing page: an oversized hero, competing panels, low information density, weak contrast, an error wall before input, and a long mobile form.

This document separates approved decisions from recommendations so later agents do not turn a suggestion into a product rule.

## Explicitly approved by Gili

### Core screen model

- This is a fast work queue, not a landing page or onboarding-style hero.
- Desktop uses a compact header with a two-pane queue and focused editor.
- Mobile starts with the queue and opens one item in a full-screen editor.

### Per-item flow

- One item uses three short steps: **Client & Project → Agreement → Payments**.
- Gili merged Client and Project on 21 August 2026 after approving the compact
  visual handoff. This replaces the earlier separate Client and Project tabs.
- Completed steps remain available for navigation.
- A new row may quietly show **Needs info**, but the editor must not open with a large wall of errors.
- Inline validation appears after a field was touched or the producer tries to continue.
- The complete missing-information list belongs in Review.
- While editing, the step's Continue action is the only primary action. Review stays secondary.
- The last step uses **Finish item**.
- A complete item becomes **Ready** and the next unfinished item opens.
- An incomplete item stays in place with exact missing fields.
- **Save for later** returns to the queue without losing work.

### Queue behavior

- Rows stay in their original order when status changes.
- Created rows stay visible but quieter.
- Progress is one compact line such as **8 items · 5 Ready · 3 Need info**, not large dashboard statistic cards.

### Visual system

- Use one clean editor surface. Do not put every section inside another card.
- Separate sections with headings, spacing, and thin dividers.
- Use two columns on desktop and one column on mobile.
- Use the Skitza display face only for the page title and step title.
- Use readable body type for fields, rows, help text, and buttons.
- Mono uppercase text is reserved for small item numbers, not important instructions.
- Use a warm cream page, clear light work surfaces, stronger borders, dark readable text, and mustard only for the selected row, current step, and primary action.
- Status always uses words and an icon, never color alone.

### Motion

- The experience should feel premium and alive.
- Use purposeful panel, selection, status, hover, and pressed transitions.
- Avoid childish motion: no confetti, bouncing, cartoon treatment, glowing buttons, or playful gimmicks.
- Motion remains fast and respects reduced-motion settings.

### Imported reminders — latest override

- Reminder selection is not optional for imported work.
- Drafting and creating the imported rows remain silent.
- **Finish setup** is mandatory and automatically activates reminders for every unpaid imported installment.
- Invitations remain optional.
- A final 50/50 reminder remains silent until exact Artist approval makes that installment due.
- Existing reminder controls after setup remain unchanged unless Gili explicitly changes them later.

### Entry-flow correction from Gili

- A normal new client joins through the producer's public Skitza link.
- Private Offers belong in Store.
- Clients & Projects must not gain a **Send private offer** or **New offer** action.
- Remove the current top-level **New client** action; do not replace it with a Private Offer action on this page.
- Remove the current **New project** action, including empty-state and legacy auto-open entry points.
- **Clients & Projects** uses **Copy my Skitza link** as its main action and **Bring in active work** as the quieter second action.
- **Bring in active work** is reachable from Clients & Projects and from the optional onboarding-completion shortcut.
- The Store's Private Offer feature itself is not removed.

## Final approval

- Gili approved the remaining entry decisions and told the team to implement this checkpoint.
- No product decision remains open for the UX redesign.
- Details not changed in this checkpoint keep the existing SK-255 behavior and safety rules. Earlier suggestions do not silently become features.

## Guardrails already fixed by SK-255

- Imported terms show **Added by producer from an existing agreement**. Never invent Artist acceptance.
- Historical producer-entered money shows **Confirmed by producer**.
- Ready rows may succeed independently; one failed or incomplete row never rolls back a successful row.
- Drafts must survive navigation and retry.
- Creation must not send invitations.
- Email-provider acceptance is the only Invited evidence. WhatsApp and Copy link never mark Invited.
- Existing ownership, payment, access, invitation, approval, and download rules remain intact unless Gili explicitly changes one.

- **Clients & Projects** now leads with **Copy my Skitza link** and keeps **Bring in active work** as the quieter second action.
- Manual **New client**, **New project**, and **New offer** entry points were removed from Clients & Projects and their direct legacy shortcuts. Store Private Offers remain unchanged.
- The import screen now uses the approved compact work queue and one focused editor surface.

  That four-step presentation is now superseded by the approved three-step
  handoff: **Client & Project → Agreement → Payments**.
